---
name: Secondary-stack awareness boundary
description: Product scope and safety boundaries for optional Connect the Thread reinforcement.
---

The user wants the secondary stack to exist only as lightweight integration context, not a second Learning Path, cumulative project structure, or scored session flow. The original five touches and their validation, hints, confidence, mode-selection, and Pride Moment rules remain authoritative.

**Why:** The user described full-stack graduation projects but explicitly requested a purely additive awareness feature rather than rebuilding primary-stack training.

**How to apply:** Keep secondary-stack work separate from concept selection, file ownership, mastery, and XP. Save normal completion before displaying optional reinforcement so skipping or closing cannot lose progress.

Preserve unfinished cached lessons without generating replacement integration content. Missing or invalid optional content must not cause retries or invalidate an otherwise valid primary lesson.

**Why:** This feature must not add Gemini calls, reset an unfinished attempt, or turn optional awareness into a completion blocker.

**How to apply:** Enrich only the existing session-generation response for opted-in users. Omit unsafe optional content rather than regenerating the primary lesson. Illustrative integrations must not imply an unbuilt endpoint or file already exists.
