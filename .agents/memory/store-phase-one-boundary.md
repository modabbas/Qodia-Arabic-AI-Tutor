Kodia never sells project code alone: every intended pack includes file-by-file explanation, defense questions, and an understanding card after passing the check.

**Why:** The user explicitly says selling code without understanding is against the product's purpose.

**How to apply:** Keep catalog claims tied to the intended pack, and distinguish that promise from functionality that has actually shipped.

Phase 1 is catalog plus interest capture only. Payment, ZIP/file delivery, explanation-pack viewing, and purchase-to-defense/understanding-card integration belong to a later request, not this one. Starter listings must be visibly coming soon; never invent sales, ratings, reviews, or urgency.

**Why:** The user deliberately limited the first phase and supplied only generic placeholder project ideas.

**How to apply:** Do not connect store activity to student sessions, learning paths, validation, hints, dashboards, or final-defense state. Use existing branding and PostgreSQL rather than replacing working systems.
