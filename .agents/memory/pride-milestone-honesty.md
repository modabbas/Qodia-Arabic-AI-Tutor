description: Why progress rewards use existing saved code without claiming unrecorded original versions.

Milestone comparisons are a read-only addition to session completion. Preserve the existing XP/streak/level stats, project persistence, learning path, validation, and hints. Use no AI requests for milestone data or labels.

**Why:** The user's brief explicitly limits this feature to existing records and an additional reward section, not changes to the teaching or persistence systems.

**How to apply:** Count genuine completed sessions rather than the capped recent-history list. Compare only owned saved code, with the latest code tied to the completed session. Missing code must never be inferred or generated.

When the oldest saved file has been edited, describe its current saved version, not an original first-written snapshot. Do not imply line-count growth when the real comparison is equal or smaller.

**Why:** Existing project files retain mutable current contents, not immutable first-written code. Adding historical snapshot writes would exceed the user's read-only scope.

**How to apply:** Label the first item as the oldest saved file, qualify edited contents, and keep all line counts factual. An immutable before/after archive requires a separately requested persistence change.
