# Fix Touch 4 Code Validation - Critical Bug

## The Bug

In Touch 4 (Build), the current validation only checks if the student's code contains certain **keywords**. This allows students to pass by writing meaningless word lists:

**Example of what currently passes (BUG):**
```
Student input: "StreamBuilder stream builder context snapshot ListView"
Result: ✓ Accepted (contains all keywords)
```

**What should happen:**
The code must actually be functional, not just a list of keywords.

## Solution: 3-Level Progressive Validation

Replace the current keyword-matching with a tiered validation system:

### Level 1: Basic Syntax Check (Free, Fast)

Verify the code is syntactically valid for the tech stack:

**For Flutter/Dart:**
- Parentheses must be balanced: `(`, `)`, `{`, `}`, `[`, `]`
- Semicolons after statements
- Proper widget tree structure (nested calls)
- At minimum: contains `(` and `)` with matching counts

**For JavaScript/React:**
- Balanced brackets
- Valid function/arrow function syntax
- JSX balance if applicable

**For Python/Django:**
- Proper indentation (minimum 1 indentation level if required)
- Colons for function definitions, loops
- Balanced parentheses

**Implementation:**
```typescript
function level1_syntaxCheck(code: string, techStack: string): { pass: boolean, reason?: string } {
  // Trim and check if empty
  if (code.trim().length < 10) {
    return { pass: false, reason: "الكود قصير جداً" };
  }
  
  // Check balanced brackets
  const open = (code.match(/[({\[]/g) || []).length;
  const close = (code.match(/[)}\]]/g) || []).length;
  if (open !== close) {
    return { pass: false, reason: "الأقواس غير متوازنة" };
  }
  
  // Must contain at least one function call or widget usage
  if (!code.includes('(')) {
    return { pass: false, reason: "لازم يكون في استدعاء دالة أو widget" };
  }
  
  return { pass: true };
}
```

### Level 2: Structure Check (Free, Fast)

Verify the code uses the required concept **structurally**, not just mentions the keyword.

**Example for StreamBuilder:**
```typescript
function level2_structureCheck(code: string, concept: string): { pass: boolean, reason?: string } {
  // Must use StreamBuilder as a widget (followed by `<` or `(`)
  const usedAsWidget = /StreamBuilder\s*[<(]/.test(code);
  if (!usedAsWidget) {
    return { pass: false, reason: "StreamBuilder مذكور لكن غير مستخدم كـ widget" };
  }
  
  // Must have required parameters (stream, builder)
  const hasStream = /stream\s*:/.test(code);
  const hasBuilder = /builder\s*:/.test(code);
  
  if (!hasStream) {
    return { pass: false, reason: "StreamBuilder يحتاج parameter اسمه stream" };
  }
  if (!hasBuilder) {
    return { pass: false, reason: "StreamBuilder يحتاج parameter اسمه builder" };
  }
  
  return { pass: true };
}
```

### Level 3: Semantic Check with Gemini (Smart)

**Only runs if Levels 1 & 2 pass.**

Send the student's code to Gemini with a focused prompt:

```
أنت مُقيّم كود في Qodia. قيّم كود الطالب التالي:

الكود المطلوب كتابته:
{task_description}

كود الطالب:
```{tech_stack}
{student_code}
```

السؤال: {level3_question}

قيّم بـ 3 معايير:
1. هل الكود صحيح نحوياً؟
2. هل يحقق الهدف المطلوب؟
3. هل يستخدم المفهوم ({concept}) بشكل صحيح؟

أرجع JSON:
{
  "is_valid": true/false,
  "score": 0-100,
  "feedback_ar": "تعليق ودي بالعربي - إذا صح: شجع، إذا غلط: وجّه بدون فضح",
  "suggestions": ["اقتراح تحسين 1", "اقتراح 2"]
}

قواعد:
- كن مدرّس ودود، مش compiler صارم
- score > 70 = اعتبره صحيح
- اللغة: عربية سورية بسيطة
- أرجع JSON فقط، بدون markdown
```

**Cost:** ~500 input tokens + 300 output = **~$0.006 per check** (Claude) or free (Gemini)

### Integration Flow

```typescript
async function validateStudentCode(code: string, session: any, user: any) {
  // Level 1: Syntax (instant)
  const level1 = level1_syntaxCheck(code, session.tech_stack);
  if (!level1.pass) {
    return {
      valid: false,
      level: 1,
      feedback_ar: level1.reason,
      can_retry: true
    };
  }
  
  // Level 2: Structure (instant)
  const level2 = level2_structureCheck(code, session.touch4_build.validation);
  if (!level2.pass) {
    return {
      valid: false,
      level: 2,
      feedback_ar: level2.reason,
      hint_ar: "راجع الـ starter code وشوف الـ parameters المطلوبة",
      can_retry: true
    };
  }
  
  // Level 3: AI semantic check (~1-2 seconds)
  const level3 = await geminiValidate(code, session, user);
  
  return {
    valid: level3.score >= 70,
    level: 3,
    score: level3.score,
    feedback_ar: level3.feedback_ar,
    suggestions: level3.suggestions,
    can_retry: level3.score < 70
  };
}
```

## Testing Requirements

**Test Case 1: Keyword soup (must fail)**
```
Input: "StreamBuilder stream builder context snapshot"
Expected: FAIL at Level 1 (not balanced, no function call)
```

**Test Case 2: Partial structure (must fail)**
```
Input: "StreamBuilder()"
Expected: FAIL at Level 2 (missing stream, builder params)
```

**Test Case 3: Valid but wrong logic (must fail)**
```
Input: StreamBuilder(stream: null, builder: (c, s) => Text("Hi"))
Expected: FAIL at Level 3 (doesn't use project's flight data)
```

**Test Case 4: Correct code (must pass)**
```
Input: Proper StreamBuilder with flightService.getFlights()
Expected: PASS all levels, score > 80
```

**Test Case 5: Edge cases**
- Empty code → Level 1 fail
- Just comments → Level 1 fail
- Code with syntax error → Level 1 fail

## Critical Requirements

1. **Preserve existing session UI** - just update the validation logic
2. **Error messages in Arabic** - friendly, teacher-like, not harsh
3. **Fast feedback** - Level 1-2 instant, Level 3 under 3 seconds
4. **Fallback** - if Gemini Level 3 fails, accept based on Level 1-2 only (don't block student)
5. **Logging** - log validation attempts to debug false positives/negatives

## Cost Impact

**Per student per session:**
- Level 1-2: $0 (local checks)
- Level 3: ~$0.006 (Gemini) or ~$0.01 (Claude)
- Average attempts to pass: 2-3

**Total added cost per student per session: ~$0.015 - $0.03**  
**Total per 30-session semester: ~$0.60 - $1.00 additional per student**

Still comfortably under $10/student threshold.

## What NOT to Do

- Do NOT change: /my-project page, dashboards, landing
- Do NOT make validation too strict (frustrates students)
- Do NOT remove the existing validation entirely (keep as fallback)
- Do NOT send huge code blocks to Gemini (truncate if > 2000 chars)
