# Qodia — Connect Gemini API to Session Generation

## Task for Replit Agent

**IMPORTANT: Enable Extended Thinking (🧠) for this critical task.**

Transform the /session page from hardcoded content to dynamic AI-generated sessions using Gemini API. Each student must see a UNIQUE session based on their project and tech stack.

## Why This Matters

**Currently:** Every student sees the same hardcoded content about Django ForeignKey.  
**After this:** Each session is generated dynamically based on the student's specific project.

This is the difference between "demo mockup" and "real AI product".

## Implementation Steps

### Step 1: Install Package

```bash
npm install @google/generative-ai
```

### Step 2: Create New API Route

**File:** `app/api/generate-session/route.ts` (or `.js`)

**Behavior:**
1. Read user identity from cookie/session
2. Fetch user's profile from Replit DB (project_name, tech_stack)
3. Check cache first (Replit DB key: `session:{user_id}:{date}`)
4. If cached, return cached session
5. If not cached, call Gemini to generate fresh session
6. Cache the result for 24 hours
7. Return JSON to frontend

## Fallback Strategy (Critical)

If Gemini fails at any point:

```typescript
try {
  const response = await gemini.generateContent(prompt);
  const cleanText = response.text()
    .replace(/```json/g, '')
    .replace(/```/g, '')
    .trim();
  const session = JSON.parse(cleanText);
  return session;
} catch (error) {
  console.error('Gemini failed:', error);
  // Return hardcoded Django ForeignKey session (existing content)
  return HARDCODED_FALLBACK_SESSION;
}
```

**User should NEVER see an error.** If AI fails, silently fall back to hardcoded content.
