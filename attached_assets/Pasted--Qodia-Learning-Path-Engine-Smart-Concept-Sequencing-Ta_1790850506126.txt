# Qodia Learning Path Engine - Smart Concept Sequencing

## Task for Replit Agent

**IMPORTANT: Enable Extended Thinking (🧠) for this architectural change.**

Transform Qodia's session generation from "random concept selection" to "intelligent learning path". No concept should repeat. Each session builds on previous ones.

## The Problem We're Solving

**Current behavior:** Each session asks Gemini "pick a concept for this student". Gemini has no memory, so it might pick StreamBuilder today and StreamBuilder again next week.

**New behavior:** 
1. On student signup, generate a full 30-concept learning path
2. Before each session, select the NEXT concept based on prerequisites and mastery
3. During session generation, send Gemini context: "Student already learned X, Y, Z. Focus on W only."
4. After session, update mastery score for that concept
5. Low-mastery concepts (<70%) get reviewed via spaced repetition

### Step 2: Select Next Concept (Before Each Session)

Update `/api/generate-session`:

Before calling Gemini, run selection logic:

```typescript
async function selectNextConcept(userId) {
  const map = await db.get(`learning_map:${userId}`);
  
  // Priority 1: Needs review (mastery < 70% from past)
  const reviewNeeded = map.concepts.filter(c => 
    c.status === "completed" && 
    c.mastery_score < 70 &&
    daysSince(c.last_reviewed) >= 3
  );
  if (reviewNeeded.length > 0) {
    return reviewNeeded[0];  // Return oldest low-mastery
  }
  
  // Priority 2: Next concept whose prerequisites are met
  const nextPlanned = map.concepts
    .filter(c => c.status === "planned")
    .find(c => {
      // All prerequisites must be completed with mastery >= 70%
      return c.prerequisites.every(prereqId => {
        const prereq = map.concepts.find(x => x.id === prereqId);
        return prereq && prereq.status === "completed" && prereq.mastery_score >= 70;
      });
    });
  
  if (nextPlanned) {
    return nextPlanned;
  }
  
  // Fallback: Any planned concept (shouldn't happen if map is well-designed)
  return map.concepts.find(c => c.status === "planned");
}
```

### Step 4: Update Mastery After Session

Create new API: `/api/update-mastery`

**Called when:** Session completes

**Logic:**
```typescript
async function updateMastery(userId, conceptId, sessionData) {
  const score = calculateMasteryScore(sessionData);
  // Formula: 
  // - Each correct touch answer = 20 points (max 100)
  // - Fast completion bonus: +5 if under 10 min
  // - Perfect code bonus: +10 if build touch passed
  
  const map = await db.get(`learning_map:${userId}`);
  const concept = map.concepts.find(c => c.id === conceptId);
  
  concept.status = "completed";
  concept.mastery_score = score;
  concept.last_reviewed = Date.now();
  concept.session_id = sessionData.id;
  
  await db.set(`learning_map:${userId}`, map);
}
```

## Backward Compatibility for Existing Users

For users who already have sessions but no learning_map:
1. On next login, generate learning_map based on their project
2. Mark concepts they already covered as "completed" with default mastery = 75
3. New sessions start filling remaining concepts
